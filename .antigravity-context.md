# Contexto Técnico: automacao-chamados-sti

## Ambiente e Infraestrutura

- **Ambiente Host:** Windows 11
- **Gerenciador de Pacotes:** Python (3.11.9)
- **Banco de Dados:** SQLite

## Estrutura de Diretórios

- `01 - Dados Brutos`: Arquivos brutos do OTRS e CitSmart em Excel.
- `02 - Dados tratados`: Arquivos de saída do pré-processamento em Excel.
- `03 - Dados prontos`: Dados passados depois do `tag_classifier.py` em Excel.
- `models`: Os arquivos joblib para treinamento do GridSearch.
- `debug_logs`: Arquivos de log gerados durante a execução dos scripts.
- `custom_select_component`: Componente de seleção personalizado, com interface mais amigável em HTML.
- `old_scripts/`: Contém scripts legados e não utilizados atualmente.
- `src/`: Contém todos os códigos-fonte, scrapers, módulos de banco de dados e utilitários.
- `tests/`: Contém os scripts de testes unitários e rascunhos de testes do Streamlit.

## Scripts de Execução

- `orquestrador.py`: Script mestre focado exclusivamente na esteira de chamados de TI (Coleta OTRS, Coleta CitSmart, Pré-processamento, Classificação de TAGs por IA).
- `dashboard.py`: Painel de visualização Streamlit e mapa de localização (Leaflet).
- `src/database/`: Camada modular DAO do SQLite (`connection.py`, `tickets_db.py`, `ramais_db.py`, `map_db.py`, `donations_db.py`, `plantoes_db.py`, `notifications_db.py`, `impressoras_db.py`, `central_db.py`, `garantia_db.py`, `events_db.py`, `unidades_db.py`, `fiscalizacao_db.py` e `__init__.py`).
- `src/scrapers/`: Todos os robôs e scrapers automatizados (`citsmart_scraper.py`, `otrs_scraper.py`, `oxe_scraper.py`, `papercut_scraper.py`, `plantoes_scraper.py`, `ramais_scraper.py`, `unidades_scraper.py`, `faq_scraper.py`).
- `src/syncs/`: Todos os workers assíncronos de sincronização em segundo plano (`sync_donations.py`, `sync_fiscalizacao.py`, `sync_garantia.py`, `sync_master.py`, `sync_portarias.py`, `sync_plantoes_alerts.py`).
- `src/components/`: Componentes reutilizáveis de interface (`header.py`, `subtabs.py`, `calendar.py`, `pagination.py`, `status_banner.py`).
- `src/scripts_powershell/`: Módulos de automação PowerShell remota (`Analisador.ps1`, `GeradorHtml.ps1`, `LimpezaEstacao.ps1`, `RemoverUsuariosLocais.ps1`). O `GeradorHtml.ps1` gera relatórios interativos com ordenação de `<th>`, filtro por tabela, ScrollSpy com sub-links de gráficos, accordions expansíveis (`.section-card`) e scrollbars customizadas.
- `src/tabs/`: Módulos de páginas isolados do dashboard (`chamados.py`, `central_telefonica.py`, `plantoes.py`, `portarias.py`, `notificacoes.py`, `redistribuicao.py`, `mapas.py`, `links_faqs.py`, `fiscalizacao.py`, `impressoras.py`, `scripts_automacao.py`, `calendario_geral.py`, `unidades.py`). O `scripts_automacao.py` permite download direto de relatórios HTML, PDF e Excel para a máquina do usuário (pronto para Docker).
- `src/preprocess_chamados.py`: Pré-processamento e normalização dos chamados brutos.
- `src/tag_classifier.py`: Treinamento e classificação de TAGs por IA (NLP spaCy e Machine Learning) com disparador seguro de fechamento de chamados antigos por base (`close_missing_tickets_by_base`).
- `src/salvar_senha.py`: Usado para persistir credenciais locais do AD no cofre do Windows (keyring).
- `tests/test_app.py`: Suíte de testes unitários integrados (41 testes cobrindo NLP, scrapers, banco e fechamento de chamados).

## Diretrizes de Interface e Compatibilidade Streamlit

1. **Parâmetro de Largura:** Utilizar estritamente `width='stretch'` para componentes responsivos de largura total (substituindo o parâmetro legado `use_container_width=True`).
2. **Componentes HTML:** Utilizar `st.components.v1.html(...)` para iframes HTML customizados (FullCalendar, Leaflet, relatórios).

## Diretrizes de Geração de Código e Formatação

1. **Fim de Linha:** Forçar sempre `LF` (\n) em todos os arquivos.
2. **Estilo de Código:** Aspas simples (`singleQuote: true`), recuo/tabulação de 2 espaços.

## RESTRIÇÃO CRÍTICA PARA ECONOMIA DE TOKENS

1. **PROIBIDO executar terminais:** A IA não deve disparar comandos ou scripts de forma automática.
2. **Apenas texto de comando:** Forneça estritamente os comandos em blocos de código markdown. O desenvolvedor os executará manualmente no terminal do WSL e devolverá as saídas no chat quando necessário.
3. **Respostas Diretas:** Sem introduções ou explicações longas. Vá direto aos dados concretos e códigos limpos.
